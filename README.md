# SkyPro Store Homework

Учебное ядро интернет-магазина на Python. Проект подготовлен по GitFlow и
использует Poetry для управления виртуальным окружением и зависимостями.

## Реализованная функциональность

- абстрактный `BaseProduct` с общим интерфейсом товаров;
- класс `Product` с названием, описанием, ценой и количеством на складе;
- `PrintMixin` с представлением `__repr__` и печатью параметров создания товара;
- наследник `Smartphone` с производительностью, моделью, памятью и цветом;
- наследник `LawnGrass` со страной-производителем, сроком прорастания и цветом;
- класс `Category` со списком товаров;
- класс `Order` с одним товаром, купленным количеством и фиксированной стоимостью;
- абстрактный `BaseEntity` с общими названием и описанием категории и заказа;
- строковые представления товаров и категорий через `__str__`;
- сложение товаров одного класса для расчёта стоимости их остатков на складе;
- проверка типа товара при добавлении в категорию;
- класс `CategoryIterator` для перебора товаров категории;
- автоматический подсчёт созданных категорий и товаров;
- загрузка категорий и вложенных товаров из JSON-файла;
- тесты моделей, абстракций, миксина, заказов, ограничений и JSON-загрузчика;
- автоматическая проверка покрытия с минимальным порогом 76%.

## Использование

```python
from src.utils import load_categories_from_json

categories = load_categories_from_json("data/products.json")
```

Цена товара хранится в приватном атрибуте `Product.__price`. Python преобразует
его имя в `_Product__price`. Читать и изменять цену следует через свойство `price`:

```python
from src.classes import Product

product = Product("Iphone 15", "512GB, Gray space", 210000.0, 8)
print(product.price)
product.price = 200000.0
```

Сеттер принимает положительную цену. При попытке установить нулевую или
отрицательную цену он выводит сообщение и сохраняет прежнее значение.
Приватное хранение цены проверяется тестами для конструктора и `new_product()`.

Строка товара содержит название, цену и остаток. Строка категории показывает
сумму остатков всех её товаров, а не количество наименований. Сложение двух
товаров одинакового класса возвращает общую стоимость их остатков и сохраняет
исходные объекты:

```python
from src.classes import Category, CategoryIterator, Product

first_product = Product("Телефон", "Описание", 100.0, 10)
second_product = Product("Чехол", "Описание", 200.0, 2)
category = Category("Техника", "Товары для дома", [first_product, second_product])

print(first_product)  # Телефон, 100.0 руб. Остаток: 10 шт.
print(category)  # Техника, количество продуктов: 12 шт.
print(first_product + second_product)  # 1400.0

for product in CategoryIterator(category):
    print(product)
```

Категорию можно перебирать и напрямую: `for product in category`.
Каждый новый `CategoryIterator(category)` начинает перебор с первого товара.
После завершения перебора `next()` вызывает `StopIteration`.

## Наследование товаров

`Smartphone` и `LawnGrass` наследуют общие поля и методы `Product`. Дополнительные
поля обязательны и передаются после названия, описания, цены и количества:

```python
from src import LawnGrass, Smartphone

smartphone = Smartphone(
    "Samsung Galaxy S23 Ultra", "256GB, Серый", 180000.0, 5,
    95.5, "S23 Ultra", 256, "Серый",
)
grass = LawnGrass(
    "Газонная трава", "Элитная трава для газона", 500.0, 20,
    "Россия", "7 дней", "Зеленый",
)
```

`efficiency` — производительность, `model` — модель, `memory` — объём памяти,
`color` — цвет смартфона. У травы `country` задаёт страну-производителя,
`germination_period` — срок прорастания строкой (например, `"7 дней"`),
`color` — цвет.

Складывать можно только товары одного конкретного класса: два `Product`, два
`Smartphone` или два `LawnGrass`. Проверка использует `type()`. Попытки сложить
смартфон с травой или обычный `Product` с его наследником вызывают `TypeError`.

`Category.add_product()` проверяет `isinstance(product, Product)` и принимает
обычные товары и любых их наследников. Название категории не ограничивает класс
товара. При передаче постороннего объекта метод вызывает `TypeError`, сохраняя
список товаров и счётчик `Category.product_count`.

## Абстрактные классы и печать создания

`BaseProduct` задаёт общий контракт: инициализация, строковое представление,
сложение, создание из словаря и чтение и изменение цены. Это абстрактный класс,
поэтому попытка создать его экземпляр вызывает `TypeError`. Конкретный
`Product(PrintMixin, BaseProduct)` реализует этот контракт. `Smartphone` и
`LawnGrass` наследуются непосредственно только от `Product`.

При создании любого товара миксин печатает одну строку с фактическим именем
класса и всеми параметрами конструктора. Например:

```python
from src import Product

product = Product("Продукт1", "Описание продукта", 1200, 10)
# Product('Продукт1', 'Описание продукта', 1200, 10)
```

`repr(product)` возвращает такое представление с текущими значениями полей,
а `str(product)` сохраняет привычный формат с ценой и остатком. У смартфона в
представление включаются производительность, модель, память и цвет; у травы —
страна, срок прорастания и цвет. Создание через `Product.new_product()` тоже
печатает ровно одну строку.

Поля представления задаются классовым кортежем `_repr_fields` в порядке
аргументов конструктора. У нового наследника с дополнительными полями нужно
расширить этот кортеж и заполнить дополнительные атрибуты до вызова `super()`.

## Заказы

`Order` и `Category` наследуют от `BaseEntity` название и описание. У заказа эти
значения копируются из купленного товара при создании. Общая база также требует
реализовать строковое представление и не допускает создания своих экземпляров.

`Order(product, quantity)` хранит ссылку на один `Product` или его наследника,
количество покупки и `total_cost`. Стоимость вычисляется при создании заказа и
сохраняется при последующих изменениях цены товара:

```python
from src import Order, Product

product = Product("Товар", "Описание", 100.5, 3)
order = Order(product, 2)
print(order.total_cost)  # 201.0
product.price = 200.0
print(order.total_cost)  # 201.0
print(product.quantity)  # 3
```

Остаток товара при создании заказа сохраняется; количество покупки может быть
больше текущего остатка. Счётчики обновляются при создании категорий и добавлении
товаров в них.
Количество покупки должно быть положительным `int`: `bool` и другие типы
вызывают `TypeError`, ноль и отрицательные значения — `ValueError`. Посторонний
объект вместо товара также вызывает `TypeError`.
